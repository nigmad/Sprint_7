# Sprint_7

# Тестирование API: Курьеры и Заказы

## Описание

Этот проект направлен на тестирование API для создания курьеров, их авторизации, а также создания и получения заказов. В рамках тестирования проверены все ключевые функциональные возможности, такие как:

- Создание курьеров
- Логин курьера
- Создание заказа
- Получение списка заказов

Кроме того, были выявлены и описаны баги, которые требуют внимания.

## Тестирование ручек



В ходе тестирования API были проверены следующие случаи:

## **Создание курьера**

- **Создание курьера:**
  - Курьера можно успешно создать при правильных входных данных.
  - Проверка на то, что невозможно создать двух одинаковых курьеров с одинаковым логином.
  - Запрос на создание курьера возвращает правильный код ответа: `201` в случае успешного создания.
  - Успешный запрос возвращает объект вида `{"ok": true}`.
  
- **Ошибки при создании курьера:**
  - Если какое-либо обязательное поле отсутствует, запрос возвращает ошибку с кодом `400`.
  - Если логин уже существует в системе, запрос возвращает ошибку с кодом `400`.

## **Для логина курьеров**

- **Успешный логин**
  - Курьер может авторизоваться при правильных логине и пароле.
  - Успешный запрос возвращает ID курьера.
  
- **Ошибки при логине**
  -  Если логин или пароль указаны неверно, запрос возвращает ошибку с кодом 400.
  - Если одно из обязательных полей отсутствует, запрос возвращает ошибку с кодом 400.
  - Если попытаться авторизоваться под несуществующим пользователем, возвращается ошибка с кодом 400

## **Создание заказа**
- **Цвета**
  - Можно указать один цвет: BLACK или GREY
  - Можно указать оба цвета.
  - Можно вообще не указывать цвет.

- **Ответ**
  - Тело ответа содержит track, который является уникальным номером заказа.

- **Ошибки**
  - Отсутствие обязательных полей в запросе вызывает ошибку с кодом 400.

## **Получение списка заказов**
  - Проверено, что запрос к ручке /api/v1/orders возвращает корректный список заказов в формате JSON. Ответ должен содержать:
  - Список заказов в поле orders.
  - Для каждого заказа — уникальный id.

После выполнения тестов был сгенерирован отчет Allure

## **Выявленные баги**
Во время тестирования были выявлены следующие баги:
 **Тест создания курьера без поля firstName:**
 - Ожидался код ответа 400, но вместо этого вернулся код 201
 
**Тест создания продублированного курьера:**
 - Тело ответа от сервера не совпадает с представленным в документации API:
Expected :'Этот логин уже используется'
Actual   :{'code': 409, 'message': 'Этот логин уже используется. Попробуйте другой.'}


## **Заключение**

Тестирование API показало, что основные ручки работают корректно, однако были выявлены проблемы с созданием учетной записи курьера, когда отсутствует обязательное поле firstName и некорректный текст тела ответа при введении уже используемого логина.
